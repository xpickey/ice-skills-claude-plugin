## 1. ทำไมเอกสารบาลีถึงยากกว่าเอกสารไทยทั่วไป
เอกสารบาลีในไทยมี **3 ระบบอักษรปนกันในหน้าเดียว**: ① ไทยร้อยแก้ว (คำอธิบาย) ② บาลีอักษรไทย (มี **พินทุ ฺ** และ **นิคหิต ํ** ซึ่งไทยปกติไม่ใช้) ③ โรมัน IAST (มี diacritics ā ī ū ṅ ñ ṭ ḍ ṇ ḷ ṃ) — เครื่องมือสกัดแต่ละตัว**เก่งคนละอย่างและพังคนละอย่าง**

## 2. อาการเสียหายที่พบจริง — แยกตามวิธีสกัด

### 2.1 ชั้นข้อความเดิม (text layer — `pdftotext` / anydoc)
| ส่วน | ผล | อาการ |
|---|---|---|
| **โรมัน IAST** | ✅ **ถูกต้องครบ** (Paṭhamā, samā, smiṃ, Puṃliṅgaṃ, ñ, ṅ, ḷ) | เป็น Latin text จริงใน PDF ไม่ผ่านฟอนต์ไทยที่พัง |
| **บาลีอักษรไทย + พินทุ** | ✅ **ถูกต้องเป็นส่วนใหญ่** (ปุริสสฺส, สฺมา, ปุริเสหิ) — พินทุอยู่ครบ (ตำรา 1,922 · สไลด์3 362) | ยกเว้นกรณีแถวถัดไป |
| **ญ / ฐ ที่มีพินทุใต้ · สระ-วรรณยุกต์บน-ล่าง** | ❌ **กลายเป็นอักขระเขต Private Use U+F700-F71B** — ปญฺญา→ป[U+F70F]ฺญา · วิญฺญาณ→วิ[U+F70F]ฺญาณ · รญฺญา→ร[U+F70F]ฺญา (ตำรา: PUA 6,500+ ตัว · พินทุกำพร้า 141 · "ญฺ" = 0 ทั้งที่ OCR มี 30) · สไลด์3 พินทุกำพร้า 24 | ฟอนต์ไทยเก็บ glyph สำรอง (ญ/ฐ ตัดหางเมื่อมีพินทุ · สระ/วรรณยุกต์เลื่อนตำแหน่ง) ไว้ในเขต PUA และ PDF ฝังรหัส PUA แทนอักขระจริง — ตัวตรวจ P7 · วิธีคืนอักขระ §2.3 · **ค้นพบโดย QA อริส (PALI-002)** |
| **ตาราง markdown** | ✅ จัดคอลัมน์ได้ดี | anydoc เก็บโครงตาราง |
| **ไทยร้อยแก้ว** | ❌ **สระอำหายทั้งไฟล์** (จำแนก→จ าแนก, กำหนด→ก าหนด) · วรรณยุกต์/สระลอย | ฟอนต์ไทย/CMap ของ PDF พัง — helper คืน **exit 3** |
| **บางไฟล์** | ❌ สระอา→ำ (คำ→คำ, ภาษา→ภำษำ) | CMap พังอีกแบบ (พบใน Pali4.pdf) |

### 2.2 OCR ในเครื่อง (macOS Vision — `--ocr` / `--ocr-all`)
| ส่วน | ผล | อาการ |
|---|---|---|
| **ไทยร้อยแก้ว** | ✅ **สระอำกลับมาครบ** (ตำรา 584 ตัว) ผ่านตัวตรวจ | OCR อ่านภาพ ไม่พึ่งฟอนต์ |
| **โรมัน IAST** | ❌ **พังหนัก**: ā→a · ū→"น" · ñ→"ที" · ṅ→n · ḷ→! · r→5 · l→1 · g→9 | OCR ไม่รู้จัก diacritics ตีความเป็นอักษรไทย/ตัวเลข |
| **พินทุ (ฺ)** | ❌ **กลายเป็นสระอุ (ุ)** — ปุตฺต→ปุตุต · สฺมา→สุมา · ตสฺส→ตสุส · รุกฺข→รุกุข | รูปคล้ายกัน (จุดใต้พยัญชนะ) — **ร้ายที่สุดเพราะได้คำบาลีที่ "ดูเหมือนถูก" แต่ผิด** |
| **นิคหิต (ํ)** | ❌ กลายเป็นการันต์ (์) — อหํ→อห์ · มยํ→มย์ · ธมฺมํ→ธมฺมิ/ธมฺม์ | |
| **ตาราง** | ❌ แตกเป็นบรรทัดเดี่ยว คอลัมน์กระจาย | OCR อ่านทีละบรรทัด |

### 2.3 คืนอักขระจากรหัส Private Use (P7) — `scripts/pali_restore_pua.py`
text layer ของ PDF ที่ฟอนต์ไทยฝัง glyph สำรอง จะให้รหัส U+F700-F71B แทนอักขระจริง — **ไม่ใช่การเดา** ถ้าตาราง mapping ได้จากหลักฐาน: script นี้ใช้ตารางที่**จับคู่คำ text layer กับ OCR ของเอกสารเดียวกันตำแหน่งต่อตำแหน่ง** (ตำราอบรม 2026.09.03: จับคู่ได้เอกลักษณ์ 1,955 คำ) และรหัสพินทุ/นิคหิตที่ OCR ยืนยันไม่ได้ ตรวจกับ paradigm แทน

| รหัส | คืนเป็น | หลักฐาน |
|---|---|---|
| U+F70A · U+F705 | ่ | 1,108 + 10 คำ ตรง 100% |
| U+F70B | ้ | 1,289 คำ ตรง 100% |
| U+F70E | ์ | 485 คำ ตรง 100% (คัมภีร์ ลิงค์) — **ไม่ใช่ ฐ** ตามที่ตารางฟอนต์มาตรฐานบางฉบับระบุ |
| U+F70F | ญ | 14 คำ 93% + paradigm (ปญฺญา วิญฺญาณ ปญฺจมี รญฺญา) |
| U+F710 · U+F701 · U+F702 · U+F712 | ั · ิ · ี · ็ | 82 · 52 · 11 · 366 คำ ตรง 100% |
| U+F71A | ฺ (พินทุ) | 96 จุด — ตรวจกับ paradigm: เสฏฺฐี วฏฺฏ ปฏฺฐาย |
| U+F71B | ํ (นิคหิต) | 17 จุด — ตรวจกับ paradigm: เอยฺยุํ อวทตฺถุํ |
| อื่น ๆ (U+F700 F703 F706 F709 F70C F711 F713) | **ไม่แปลง** | ตัวอย่าง <10 หรือคะแนนต่ำ (F711 33%) — script คงไว้และรายงานให้ตรวจด้วยตา |

ผลจริงกับตำรา (คัดจาก output ของ `--report`): คืน 6,544 ตัว จาก 11 รหัส · ญฺ 0 → 138 · พินทุกำพร้า 141 → 3 · เหลือ PUA ที่ต้องดูเอง ~56 ตัว · **สระอำยังหายเหมือนเดิม** (ไม่ได้อยู่ในเขต PUA — ร้อยแก้วไทยยังต้องใช้ OCR ตาม §2.4) · **เอกสารจากฟอนต์อื่นอาจใช้รหัสต่างกัน** — ถ้า `pali_check.sh` ยังขึ้น P7 หลังคืน ให้จับคู่กับ OCR ใหม่ตามวิธีเดียวกัน ห้ามใช้ตารางนี้กับเอกสารอื่นโดยไม่ตรวจตัวอย่างก่อน
```bash
python3 ~/.claude/skills/pali-language/scripts/pali_restore_pua.py <text-layer.md> -o <text-layer-restored.md>   # แล้วรัน pali_check.sh ซ้ำ
```

### 2.4 สรุปเป็นกฎ: **แหล่งสองทางเสริมกัน (Dual-source)**
```
เนื้อหาบาลี (ตาราง · โรมัน IAST · อักษรไทยมีพินทุ/นิคหิต)  →  ใช้ text layer
คำอธิบายไทยร้อยแก้ว (สระอำ/วรรณยุกต์)                    →  ใช้ OCR
```
**ห้ามใช้ OCR เป็นแหล่งเดียวของคำบาลี** และ **ห้ามใช้ text layer เป็นแหล่งเดียวของร้อยแก้วไทย**

## 3. Workflow มาตรฐาน (5 ขั้น)
| ขั้น | คำสั่ง | ได้อะไร | ถ้าไม่ผ่านทำอะไร |
|---|---|---|---|
| ① คัดกรอง | `bash ~/.claude/agents/_lib/doc_to_md.sh --scan <DIR>` | ไฟล์ไหน text_based/scanned · หน้าไหนต้อง OCR | scanned ทั้งไฟล์ → ข้ามไป ③ ด้วย `--ocr-all` |
| ② สกัด text layer | `doc_to_md.sh <FILE> -o <name>.md` | MD ที่โรมัน/พินทุถูก · **คาดว่า exit 3** (ไทยเสีย) — ปกติสำหรับเอกสารบาลี | exit 2 (อ่านไม่ได้เลย) → ③ |
| ③ สกัด OCR | `doc_to_md.sh <FILE> --ocr-all -o <name>-ocr.md` | MD ที่ไทยร้อยแก้วถูก (~1.8 วิ/หน้า) | ยัง exit 3 → บันได R2b ของ ice-doc-reader (ขอต้นฉบับ / ส่งภายนอกโดยขออนุญาต) |
| ④ ตรวจเฉพาะบาลี | `bash ~/.claude/skills/pali-language/scripts/pali_check.sh <name>.md <name>-ocr.md` | รายงานอาการ §2 ทั้งสองไฟล์ + แนะนำว่าส่วนไหนใช้ไฟล์ไหน (exit 3 = มี 🔴 ซึ่งเป็นปกติของแหล่งดิบ) | P7 ขึ้นที่ text layer → คืนอักขระตาม §2.3 ก่อนขั้น ⑤ |
| ⑤ ประกอบ + provenance | อ่านทั้งสองไฟล์คู่กัน: คำบาลี/ตาราง ← text · ร้อยแก้ว ← OCR · บันทึก provenance ว่าส่วนใดมาจากแหล่งใด | Markdown สะอาดพร้อมใช้ | คำที่สองแหล่งขัดกันและตัดสินไม่ได้ → **flag ไว้ ห้ามเดา** |

**ทางลัด:** `bash ~/.claude/skills/pali-language/scripts/pali_extract.sh <FILE.pdf> <outdir>` ทำขั้น ①-④ ให้ในคำสั่งเดียว (ดู §6)

## 4. รายการตรวจสอบเฉพาะบาลี (ที่ตัวตรวจไทยทั่วไปไม่จับ)
| # | ตรวจอะไร | วิธี | ผิดปกติเมื่อ |
|---|---|---|---|
| P1 | **พินทุ→สระอุ** ทั้งไฟล์ (OCR) | นับ "สระอุ+พยัญชนะ" `[พยัญชนะ]ุ[พยัญชนะ]` เทียบกับจำนวนพินทุ ฺ — **🔴 เมื่อสระอุแบบนี้ ≥20 และมากกว่าจำนวนพินทุ** | ตัวเลขดิบของ pattern นี้ใช้ตัดสินไม่ได้ เพราะนับคำถูกอย่าง พุทฺธ ทุติยา ปุตฺต ด้วย (ตำรา text layer ที่พินทุครบก็ได้ 457) · ที่แยกได้จริงคือ**อัตราส่วนต่อพินทุ**: OCR ตำรา 696:179 🔴 · OCR สไลด์3 136:73 🔴 · text layer ตำรา 457:1,922 ✓ · text layer Pali1 18:27 ✓ (แก้ตาม QA อริส PALI-001) |
| P2 | **นิคหิตหาย** — คำบาลีลงท้าย ์ | หา `[ก-ฮ]์` ในคอลัมน์บาลี | ํ→์ (อห์ มย์) |
| P3 | **IAST เพี้ยน** — อักษรไทย/ตัวเลขแทรกในคอลัมน์โรมัน | หา `[a-z]+[ก-๙0-9!]+[a-z]*` | ū→น ñ→ที ḷ→! |
| P4 | **diacritics หาย** — โรมันไม่มี ā ī ū ṅ ñ ṭ ḍ ṇ ḷ ṃ เลยทั้งไฟล์ | นับ diacritics | เอกสารบาลีโรมันจริงต้องมี (สถิติ: ไฟล์สไลด์ 25 หน้า มี >100 ตัว) |
| P5 | **ตารางแตก** | ⚠ เมื่อไม่มีบรรทัด `|` เลย แต่มีบรรทัดสั้น ≤12 อักขระ ≥50 บรรทัด | OCR ทำตารางกระจาย (ตำรา text layer 733 บรรทัดตาราง · OCR 1) |
| P6 | **สระอำ = 0** ทั้งที่ไทย ≥1,000 อักขระ | 🔴 (ice-doc-reader ตรวจให้แล้วเช่นกัน) | text layer พัง |
| P7 | **อักขระ Private Use / พินทุกำพร้า** | 🔴 เมื่อพบ U+F700-F8FF หรือ ฺ ที่ไม่มีพยัญชนะไทยนำหน้า | ญ/ฐ ก่อนพินทุ และสระ/วรรณยุกต์ถูกแทนด้วย glyph สำรอง (§2.1 แถว 3) — ต้องคืนอักขระตาม §2.3 ก่อนใช้คำบาลีจาก text layer |
**ผลลัพธ์ที่คาดของแต่ละแหล่ง:** text layer ของ PDF ฟอนต์พัง = 🔴 P6 (+P7 บ่อย) · OCR = 🔴 P1 · **ไฟล์ที่ประกอบ dual-source เสร็จแล้วต้องได้ exit 0** — script คืน exit 3 เมื่อพบ 🔴 ข้อใดข้อหนึ่ง

## 5. กฎการตัดสินเมื่อสองแหล่งขัดกัน
1. **คำบาลี:** เชื่อ text layer ก่อน · ถ้า text layer ก็เพี้ยน → เทียบ**รูปโรมัน IAST** ในบรรทัดเดียวกัน (มักถูก) → เทียบ paradigm ในไฟล์ `02`/`03`/`04` → ยังตัดสินไม่ได้ = flag `[?]` ไว้
2. **ร้อยแก้วไทย:** เชื่อ OCR ก่อน · OCR ผิดคำ (ตัวอย่างจริง: "มาครี" แทน "มาคธี") → เทียบ text layer ที่สระอำหายแต่พยัญชนะถูก
3. **ตัวเลข/เลขหน้า/ชื่อเฉพาะ:** ต้องตรงกัน**ทั้งสองแหล่ง**จึงใช้ · ไม่ตรง = เปิดหน้า PDF ดูด้วยตา (Read + pages)
4. **ห้ามเดา** — คำที่ตัดสินไม่ได้ ให้คงรูปที่พบ + `[?]` + หมายเหตุ ดีกว่าคำที่ "ดูถูก" แต่กุขึ้น

## 7. ฟอร์แมตปลายทางอื่น
| ต้องการ | วิธี |
|---|---|
| **Markdown** (ค่าเริ่มต้น) | ผลจาก §3 ⑤ |

## 8. เก็บเข้าคลัง (provenance บังคับ)
frontmatter ของ MD ที่ประกอบแล้ว ต้องมี: `source:` (ไฟล์ต้นทาง) · `extracted:` (วันที่) · `method: dual-source (text-layer for Pali, OCR for Thai prose)` · `thai_check:` (ผล exit code ของแต่ละแหล่ง) · `pali_check:` (สรุป P1-P7 + exit code ของไฟล์ที่ประกอบแล้ว ต้องเป็น 0) · `pua_restored:` (จำนวนอักขระที่คืนตาม §2.3 ถ้ามี) · `unresolved:` (จำนวนคำที่ flag `[?]`) — ไม่มี provenance = ใช้อ้างอิงไม่ได้ (กติกา ice-doc-reader R4)
