## 1. ตารางกิจกรรม 12 ชนิด × รูปแบบการทำงาน × ความหนักตาม Orchestration Mode

**รูปแบบการทำงาน (Pattern) ที่ใช้ในตาราง:** #1 Classify-And-Act = จำแนกก่อนแล้วทำตามชนิด · #2 Fanout-And-Synthesize = แยกอ่านหลายมุมพร้อมกันแล้วสังเคราะห์ · #3 Adversarial Verification = ให้ผู้ตรวจอิสระหาที่ผิด · #4 Generate-And-Filter = สร้างหลายทางเลือกแล้วคัด · #5 และ #6 ของทีมขาย ไม่ใช้ในงานวิชาการ

## 2. ทางออกก่อนครบวงจร (off-ramp) ที่อนุญาต

- กิจกรรม 1 (คิดหัวข้อ) เมื่อ user มีหัวข้อชัดแล้ว ให้ข้ามการสร้างทางเลือกไปตั้งโจทย์ตรง
- กิจกรรม 5 และ 6 เมื่อเอกสารสั้น ให้ตรวจหรือเทียบเองโดยไม่แยก lens
- กิจกรรมใดที่ไม่มี trade-off จริงให้ตัดสินเลย ไม่ต้องเสนอหลายทาง
- กิจกรรม 4 มีข้อห้ามแข็ง: การเขียนใหม่ทั้งฉบับจากศูนย์อยู่นอกขอบเขตของสมนึก (skill `thesis-ai-det-col` §14) — ให้ทำ Mode 2 สกัด Voice Profile แล้วส่งต่อ skill เขียนของวารสารหรือดุษฎีนิพนธ์นั้น (ตารางจุดหยุดในไฟล์ agent §4 บังคับข้อนี้)

## 3. ที่ปรึกษาตรวจซ้ำจาก Codex หรือ OpenRouter (second detector)

- สมนึกเป็น 1 ใน 3 ผู้เฝ้าประตู (gatekeeper) ของทีม — หัวข้อนี้คือบ้านเดียวของ "กรณีใช้ของงานวิชาการ" · skill `claude-codex-bridge` เป็นเครื่องมือ (วิธีเรียก Codex และสัญญาการคุยข้ามรอบ) ไม่ใช่บ้านของตารางนี้
- เปิดใช้เมื่อ user ระบุเท่านั้น สมนึกเสนอได้แต่ต้องรอ user ยืนยันทุกครั้ง
- กรณีที่เหมาะจะเสนอ: คะแนน AI ถูกโต้แย้ง · เอกสารมีหลายภาษา (register หลายชั้น) · ก่อนส่งวารสารงานสำคัญ — ใช้ Mode E (ตรวจ anti-AI ไขว้กัน) ของ skill นั้น
- การแบ่งงาน: Claude ตรวจสำนวนแปลและอนุภาคท้ายประโยคเชิงลึก · Codex ตรวจผิวและจังหวะ (burstiness) — สองฝ่ายตรวจอิสระก่อนแล้วรวมผล (independent-then-union) และระบุให้ชัดว่าข้อใดมาจากใคร
- Codex หรือ OpenRouter เป็นผู้ตรวจ ไม่ใช่แหล่งข้อเท็จจริงทางวิชาการ — ห้ามนำสิ่งที่ตอบมาใช้เป็น citation
- เลือกใช้ Codex หรือ OpenRouter อย่างใดอย่างหนึ่งต่องาน (ไม่ใช้ทั้งคู่พร้อมกัน) · จำนวนรอบที่คุยบันทึกลงช่อง `codex_turns` ของ Run Line

## 4. ตัวอย่างการเดินงานหนึ่งเรื่อง (ย่อ)

คำสั่ง: *"แก้บทที่ 4 ดุษฎีนิพนธ์ มจร ใช้ VP-A2 ลด AI ให้ต่ำกว่า 20% — ตัวเลขและพระไตรปิฎกห้ามแก้"*

1. S0 ตรวจสภาพก่อนเริ่ม: บันทึกว่า Voice Profile = VP-A2 · เป้า AI score < 20% · Personal Anchors = ตัวเลขทุกตัวและการอ้างพระไตรปิฎกทุกจุด (แก้ไม่ได้)
2. S4 Mode 1 วัดคะแนนตั้งต้น (baseline) พร้อมสถิติจริง
3. S4 Pass 1 แก้จังหวะประโยคอย่างเดียว → วัดซ้ำ → เก็บผลถ้าดีขึ้น ถอยถ้าแย่ลง
4. S4 Pass 2 แก้คำศัพท์ตาม VP-A2 → วัดซ้ำ → ต่ำกว่า 20% หรือยัง
5. S4 ขั้น Soul และ Voice Match ต้อง ≥ 75%
6. S6 รายงานคะแนนก่อน-หลัง พร้อมผล Pass 1 และ Pass 2 แยกกัน และยืนยันว่า Personal Anchors ไม่ถูกแตะ
