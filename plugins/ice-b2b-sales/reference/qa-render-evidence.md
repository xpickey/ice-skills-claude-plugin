# หลักฐานการตรวจของผู้ตรวจคุณภาพ (อริส) — การ render สด · ที่เก็บไฟล์ระหว่างตรวจ · ความสดของหลักฐาน

> **Version:** V01R01 | **Date:** 2026.09.05 | ย้ายออกมาจากไฟล์ agent `qa-master-agent.md` ขั้น E4 (Pass 3 ของแผนแก้ทีม)
> **ไฟล์นี้ใช้ทำอะไร:** บอกอริสว่าจะได้ภาพจริงของเอกสารมาตรวจมิติหน้าตา (D7) อย่างไร เก็บไฟล์ที่เกิดระหว่างตรวจไว้ที่ไหน และหลักฐานแบบไหนใช้ตัดสินได้
> **ใครใช้:** อริส (agent `qa-master-agent`) ในขั้น E3 และ E4 ของไฟล์ agent
> **เรื่องที่ไม่อยู่ในไฟล์นี้และอยู่ที่ใด:** บันไดการ render ฉบับเต็ม (ห้ามใช้ `soffice` จาก PATH เพราะเป็นตัวปลอมที่มองไม่เห็นฟอนต์ · ตัวช่วย `render_pdf.sh` · การตรวจฟอนต์หลัง render ด้วย `pdffonts`) อยู่ที่ skill `~/.claude/skills/ice-doc-builder/SKILL.md` §7 ซึ่งเป็นบ้านเดียว · กติกาที่เก็บไฟล์ชั่วคราวของทั้งทีม อยู่ที่ `~/.claude/agents/reference/file-hygiene.md`

## 1. การ render — เรียกตัวช่วยกลาง แล้วแปลงเป็นภาพ

1. รัน `bash ~/.claude/agents/_lib/render_pdf.sh <ไฟล์> <sub-project>/20-Output/_temp/qa/ --expect "<ชื่อฟอนต์ตามที่ปรากฏใน PDF>" --strict-fonts` — ตัวช่วยหาโปรแกรม LibreOffice ตัวจริงและตรวจฟอนต์ที่ฝังใน PDF ให้ในตัว · สงสัยว่าเครื่องมือผิดตัว ให้รัน `render_pdf.sh --which` ก่อน · ผล `pdffonts` ที่เจอชื่อ LinuxLibertine FrankRuhl DejaVu หรือ Liberation แปลว่าเครื่อง render มองไม่เห็นฟอนต์ระบบ ให้หยุดและตรวจเครื่องมือก่อน อย่ารายงานเป็นข้อบกพร่องของไฟล์ (รายละเอียดที่ ice-doc-builder §7)
2. แปลง PDF เป็นภาพรายหน้าด้วย `/opt/homebrew/bin/pdftoppm -png -r 100 <ไฟล์.pdf> <sub-project>/20-Output/_temp/qa/<ชื่อ>` (ความละเอียด 100 ถึง 130 พอสำหรับตรวจ สูงกว่านั้นเปลืองโดยไม่ได้อะไรเพิ่ม) · เครื่องมือรายงานว่าสำเร็จไม่ได้แปลว่าไฟล์เกิดจริง — ใช้ `ls` ยืนยันทุกครั้งก่อนเปิดดู
3. render ครั้งเดียวต่อรอบ แล้วใช้ภาพชุดเดียวตรวจทุกมิติ · สงสัยจุดใดให้ขยายดูเฉพาะจุด ไม่เริ่มใหม่ทั้งชุด

**ทางเลือกเมื่อ LibreOffice ใช้ไม่ได้:**
- **PowerPoint ผ่าน AppleScript** (ความเที่ยงตรงสูงสุด): คำสั่ง save as PDF ต้องระบุปลายทางเป็น `POSIX file "..."` — ส่งเป็นข้อความธรรมดาจะได้คำตอบว่าเสร็จแต่ไม่มีไฟล์ · sandbox ของ PowerPoint เขียนบางที่ไม่ได้ ให้บันทึกผ่านโฟลเดอร์พัก `~/Documents/.ice-staging/` แล้วย้ายเข้า `_temp/qa/` ในคำสั่งเดียวกัน (`osascript … && mv …`) ห้ามทิ้งค้าง
- **เครื่องมือ PowerPoint MCP**: ใช้ได้เฉพาะเช็คว่าไฟล์เปิดได้จริงโดยไม่ขึ้นกล่อง Repair (การเปิดใน PowerPoint จริงเป็นหน้าที่ของอริสในรอบตรวจ เพราะ LibreOffice ปล่อยไฟล์ที่ PowerPoint จะปฏิเสธ) — คำสั่ง export PDF ของเครื่องมือนี้เชื่อไม่ได้ เพราะรายงานสำเร็จโดยไม่เขียนไฟล์
- **ทุกทางใช้ไม่ได้:** ประกาศตรง ๆ รายมิติในซองผลงานว่า "ตรวจไม่ได้บนเครื่องนี้" ห้ามเดาผล และห้ามหยิบภาพเก่ามาตรวจแทน

## 2. ที่เก็บไฟล์ระหว่างตรวจ

ไฟล์ทุกชนิดที่เกิดระหว่างตรวจ (PDF ภาพรายหน้า ภาพขยาย ไฟล์เทียบ แฟ้มความคืบหน้า) ต้องอยู่ที่ `<sub-project>/20-Output/_temp/qa/` เท่านั้น · ห้ามสร้างไฟล์นอกโฟลเดอร์งานเด็ดขาด ที่สำคัญคือห้ามวางใต้ `~/Documents` (เคยเกิดจริง 2026.08.05 และ user เป็นผู้พบเอง) · ข้อยกเว้นเดียวคือโฟลเดอร์พัก `~/Documents/.ice-staging/` สำหรับเส้นทาง PowerPoint AppleScript ตามหัวข้อ 1 ซึ่งต้องย้ายออกในคำสั่งเดียวกันเสมอ · ไม่แน่ใจที่เก็บให้ถามผู้เรียกในคำถามชุดเดียวของขั้น E0 · จบรอบ เก็บเฉพาะหลักฐานที่อ้างถึงในผลตรวจ ลบที่เหลือ แล้ว `ls` ยืนยันว่าไม่มีไฟล์หลงผิดที่

## 3. ความสดของหลักฐาน

คำตัดสินเรื่องหน้าตาเอกสารต้องมาจาก render สดของไฟล์รุ่นปัจจุบันในรอบนี้เท่านั้น · ห้ามใช้ภาพหรือ PDF จาก session เก่าหรือจากไฟล์คนละรุ่น (เคสจริง Akara: ตรวจจากภาพเก่าแล้วรายงานข้อบกพร่องที่แก้ไปแล้ว) · บันทึกคำสั่ง render ความละเอียด และเวลา ไว้ในผลตรวจทุกรอบ เพื่อให้ผู้เรียกลงบรรทัด "Render evidence" ใน QA log ได้ · render ไม่ได้ให้บอกตรง ๆ ว่ามิติใดตรวจไม่ได้

## 4. หลักฐานต่อมิติและแฟ้มความคืบหน้า

ทุกมิติแนบหลักฐานที่เปิด นับ หรือเทียบจริง เช่น "มิติ D3: เปิดหน้า 12 และ 34 นับจำนวนรายการเทียบตารางราคาแล้วตรงกัน" — คำตัดสินที่ไม่มีหลักฐาน = งานยังไม่เสร็จ · รายงานเป็นตัวเลขเสมอ ("ข้อความซ้อน 0 · ล้นขอบ 0 · ฟอนต์ฝัง 4/4") ไม่รายงานว่า "ผ่านแล้ว" ลอย ๆ · ระหว่างตรวจ เขียนบรรทัดความคืบหน้าลง `<sub-project>/20-Output/_temp/qa/_qa-progress.md` ทีละมิติที่จบ เพื่อให้ผู้เรียกเฝ้าดูว่างานเดินอยู่ — ผู้เรียกมีสิทธิ์หยุดงานเมื่อไฟล์นี้เงียบเกินประมาณ 15 นาที
