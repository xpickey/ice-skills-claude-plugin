## เรานำเข้าอะไรมาแล้วบ้าง

นำเข้า **agent skill ของ Oracle ทั้ง 10 ชุด** จากโฟลเดอร์ `packages/agent-skills` มาไว้ที่
`plugins/ice-b2b-sales/skills/` โดยใช้ชื่อโฟลเดอร์เดิมของ Oracle ทุกตัว การคงชื่อเดิมไว้มีเหตุผลชัดเจน
คือทำให้เทียบกับต้นทางได้ตรงตัวเมื่อ Oracle ออกของใหม่ ถ้าเปลี่ยนชื่อหรือรื้อโครงสร้างไฟล์ใหม่
ความสามารถในการเทียบจะหายไปทันที และเราจะไม่มีทางรู้ว่าของในมือเก่าไปแล้วหรือยัง

รายชื่อทั้ง 10 ชุด แบ่งตามลักษณะงาน:

| กลุ่มงาน | skill |

| จัดโครงสร้างและติดตั้งโครงการ | `netsuite-sdf-safe-guide` · `netsuite-sdf-project-documentation` · `netsuite-sdf-roles-and-permissions` · `netsuite-uif-spa-reference` |

## เราตั้งใจไม่นำเข้าอะไร และเพราะอะไร

คลังโค้ดต้นทางมีขนาดประมาณ 20 เมกะไบต์ ส่วนที่เป็นความรู้คือ `packages/agent-skills` เท่านั้น
(ประมาณ 5.4 เมกะไบต์เมื่อรวมไฟล์ประกอบ) ส่วนที่เหลือเป็นซอฟต์แวร์ที่รันได้ ได้แก่ `node-cli`
(SuiteCloud CLI) · `vscode-extension` (ส่วนขยายของโปรแกรมแก้ไขโค้ด) · `sdk-core` · `unit-testing` ·
`ai-plugins` · `uif-types`

**เหตุผลที่ไม่เอาซอฟต์แวร์เหล่านั้นเข้ามา** มีสามข้อ ข้อแรก มันไม่ใช่ความรู้ที่ agent อ่านแล้วตอบได้
แต่เป็นโปรแกรมที่ต้องติดตั้งลงเครื่องจึงจะใช้งาน ข้อสอง Oracle เผยแพร่ผ่านช่องทางติดตั้งมาตรฐานอยู่แล้ว
การเก็บสำเนาไว้ใน plugin จะได้สำเนาที่เก่าลงทุกวันโดยไม่มีใครรู้ ซึ่งขัดกับหลักที่ทีมยึดว่าห้ามเก็บสำเนา
ข้ามชั้น ข้อสาม ทุกคนที่ติดตั้ง plugin นี้จะต้องดาวน์โหลดตามไปด้วยทั้งที่งานขายและงานให้คำปรึกษา
ส่วนใหญ่ไม่ได้ใช้

**เมื่อต้องใช้ SuiteCloud CLI จริง** ให้ติดตั้งจากช่องทางของ Oracle โดยตรงด้วยคำสั่งข้างล่างนี้
ซึ่งต้องมีโปรแกรม Node.js อยู่ในเครื่องก่อน คำสั่งจะติดตั้งรุ่นล่าสุดที่ Oracle เผยแพร่:

```
npm install -g @oracle/suitecloud-cli
```

ตรวจว่าติดตั้งสำเร็จด้วย `suitecloud --version` ถ้าคำสั่งไม่ถูกพบ แปลว่ายังไม่มี Node.js
หรือโฟลเดอร์ของ npm ยังไม่อยู่ในตัวแปร PATH ให้ติดตั้ง Node.js ก่อนแล้วรันคำสั่งข้างบนซ้ำ

## ของที่ทีมแก้เองและต้องรักษาไว้ทุกครั้งที่ดึงของใหม่

มีสองอย่าง ถ้าใครคัดลอกไฟล์จากต้นทางทับลงไปตรง ๆ ทั้งสองอย่างนี้จะหายทันทีโดยไม่มีข้อความเตือน

**อย่างที่หนึ่ง — ช่อง `description` ภาษาไทยในทุกไฟล์** ต้นทางเขียนช่องนี้เป็นภาษาอังกฤษ ทีมแปลเป็นไทย
พร้อมต่อท้ายด้วยรายการคำกระตุ้น เพราะตัวจัดเส้นทางและตัวเลือก skill ของระบบอ่านช่องนี้เพื่อตัดสินว่า
งานที่ผู้ใช้พิมพ์เป็นภาษาไทยตรงกับ skill ตัวใด **ถ้าช่องนี้กลับไปเป็นภาษาอังกฤษ skill จะเงียบเมื่อผู้ใช้
พิมพ์ไทย** ซึ่งเป็นผู้ใช้หลักของระบบนี้ ผลคือความรู้ยังอยู่ในเครื่องครบแต่ไม่มีใครเรียกใช้ได้

**อย่างที่สอง — หัวข้อ REST Web Services ใน `netsuite-suitescript-records-reference`** ทีมสกัดโครงสร้าง
record ฝั่ง REST จำนวน 151 ชนิดจาก REST API Browser รุ่น 2024.2 เมื่อ 2026.08.07 แล้วเพิ่มเป็นหัวข้อ
ในไฟล์พร้อมไฟล์ประกอบชื่อขึ้นต้น `references/rest-` ต้นทางของ Oracle ไม่มีส่วนนี้ **ถ้าส่วนนี้หายไป
ทีมจะตอบคำถามเรื่องชื่อ field ฝั่ง REST ไม่ได้ และจะเผลอตอบด้วยชื่อ field ฝั่ง SuiteScript ซึ่งเป็น
คนละชุดกัน** ความผิดพลาดแบบนี้ไม่แสดงอาการตอนตอบ แต่ไปแสดงตอนลูกค้านำไปเขียนโปรแกรมจริงแล้วเรียกไม่ติด

## วิธีตรวจว่าของในมือเก่าหรือยัง

อย่าตัดสินด้วยสายตาหรือด้วยความจำ ให้รันเครื่องตรวจที่ทีมเขียนไว้ **ทุกคำสั่งในไฟล์นี้เขียนเป็น path
แบบสัมพัทธ์ จึงต้องยืนที่รากของคลังโค้ด `iCE-Skills-Marketplace` ก่อนเสมอ** (ตัวสคริปต์เองหาโฟลเดอร์
skills จากตำแหน่งไฟล์ของตัวเอง ถ้าจำเป็นต้องรันจากที่อื่นจริงจึงต้องเขียน path เต็มถึงตัวสคริปต์):

```
python3 plugins/ice-b2b-sales/_lib/netsuite_skill_sync_check.py
echo $?
```

**สิ่งที่ต้องมีก่อนรัน:** ต้องติดตั้ง GitHub CLI (คำสั่งชื่อ `gh`) และเข้าสู่ระบบด้วย `gh auth login` แล้ว
และเครื่องต้องต่ออินเทอร์เน็ตได้ เพราะเครื่องตรวจดึงไฟล์จากต้นทางมาเทียบสดทุกครั้ง

**เครื่องตรวจครอบคลุมสี่เรื่อง** ในการรันครั้งเดียว: เทียบเนื้อความของ `SKILL.md` ทุกตัวโดยข้ามส่วนหัว
frontmatter · ตรวจแยกอีกชั้นว่าช่อง `description` ยังเป็นภาษาไทยอยู่ (จำเป็นเพราะการเทียบเนื้อความข้ามส่วนนั้นไป
ถ้าไม่ตรวจซ้ำ การคัดลอกทับที่ทำให้ description กลับเป็นภาษาอังกฤษจะไม่มีใครเห็น) · เทียบไฟล์ประกอบใน
โฟลเดอร์ `references/` ทีละไฟล์ พร้อมรายงานไฟล์ที่ขาด ไฟล์ที่เกิน และไฟล์ที่เนื้อหาต่าง · และรายงาน
skill ชุดใหม่ที่ Oracle เพิ่มเข้ามาแต่เรายังไม่ได้นำเข้า

**รหัสจบของคำสั่ง** มีสามค่า และค่าที่ต้องระวังที่สุดคือ 2 เพราะแปลว่ายังไม่รู้ผล ไม่ใช่ว่าผ่าน:

| รหัสจบ | ความหมาย | ต้องทำอะไรต่อ |
|---|---|---|
| 0 | ไม่พบเรื่องที่ต้องจัดการ | ไม่ต้องทำอะไร |
| 1 | พบเรื่องที่ต้องจัดการ | อ่านรายการท้ายผล แล้วทำตามหัวข้อถัดไป |
| 2 | ตรวจไม่สำเร็จ เช่น ไม่มีคำสั่ง `gh` หรือดึงข้อมูลจากต้นทางไม่ได้ | แก้สาเหตุที่ข้อความบอกแล้วรันซ้ำ **ห้ามสรุปว่าของในมือตรงกับต้นทาง** |

## เมื่อเครื่องตรวจฟ้องว่ามีเรื่องต้องจัดการ

ห้ามคัดลอกไฟล์จากต้นทางทับทันที ให้ทำสามขั้นนี้

**ขั้นที่หนึ่ง — ดูความต่างจริงก่อน** ด้วยสองคำสั่งนี้ แทน `<ชื่อ skill>` ด้วยชื่อโฟลเดอร์ที่เครื่องตรวจฟ้อง:

```
gh api repos/oracle/netsuite-suitecloud-sdk/contents/packages/agent-skills/<ชื่อ skill>/SKILL.md --jq .content | base64 -d > /tmp/upstream-SKILL.md
diff /tmp/upstream-SKILL.md plugins/ice-b2b-sales/skills/<ชื่อ skill>/SKILL.md
```

ถ้าเรื่องที่ฟ้องเป็นไฟล์ประกอบ ให้เปลี่ยน `SKILL.md` ในทั้งสองคำสั่งเป็น path ของไฟล์นั้น
เช่น `references/rest-record-api.md`

**ขั้นที่สอง — รวมของใหม่เข้ากับของเราด้วยมือ** โดยคงสามสิ่งไว้เสมอ คือช่อง `description` ภาษาไทย
พร้อมคำกระตุ้น · หัวข้อ REST Web Services กับไฟล์ `references/rest-` · และช่อง `license`
ถ้าความต่างนั้นเป็นของที่ทีมตั้งใจเพิ่มใหม่และตรวจแล้ว ให้ขึ้นทะเบียนในตัวแปร `KNOWN_LOCAL_EDITS`
ที่หัวไฟล์สคริปต์ พร้อมคำอธิบายว่าเพิ่มอะไร เมื่อไหร่ และถ้าหายจะเกิดผลเสียอะไร — **ห้ามขึ้นทะเบียน
เพื่อกลบผลที่ยังไม่ได้ตรวจ** เพราะจุดประสงค์ของทะเบียนคือทำให้ผลที่เหลือน่าเชื่อถือ ไม่ใช่ทำให้ผลผ่าน

ทะเบียนนั้นใช้ชื่อโฟลเดอร์ของ skill เป็นกุญแจ และมีสองช่อง คือ `note` สำหรับคำอธิบายที่จะแสดงในผลตรวจ
และ `extra_files` สำหรับชื่อขึ้นต้นของไฟล์ประกอบที่ทีมเพิ่มเอง เพื่อไม่ให้เครื่องตรวจฟ้องว่าเป็นไฟล์แปลกปลอม:

```python
KNOWN_LOCAL_EDITS = {
    "netsuite-suitescript-records-reference": {
        "note": "หัวข้อ REST Web Services ... เพิ่มเมื่อ 2026.08.07 ... ถ้าหายจะเกิดผลเสียคือ ...",
        "extra_files": ["references/rest-"],
    },
}
```

**ขั้นที่สาม — รันเครื่องตรวจซ้ำจนได้รหัสจบ 0**

❌ เห็นว่าต้นทางมีของใหม่ แล้วสั่งคัดลอกทั้งโฟลเดอร์ทับของเดิม (ช่อง description ไทยและหัวข้อ REST หายทั้งชุด)
✅ ดูความต่างทีละไฟล์ นำเฉพาะเนื้อใหม่ของ Oracle มารวมกับของเรา คงสามสิ่งข้างต้นไว้ แล้วรันเครื่องตรวจซ้ำ

## เมื่อ Oracle ออก skill ชุดใหม่ที่เรายังไม่มี

เครื่องตรวจจะรายงานชื่อชุดใหม่ให้เองในหัวข้อท้ายผล การนำเข้าไม่ใช่แค่คัดลอกโฟลเดอร์ ต้องทำสามอย่าง
คู่กันเสมอ มิฉะนั้นความรู้จะอยู่ในเครื่องแต่ไม่มีใครเรียกใช้ได้:

1. คัดลอกโฟลเดอร์ของ skill นั้นเข้า `plugins/ice-b2b-sales/skills/` โดยคงชื่อเดิมของ Oracle
2. แปลช่อง `description` เป็นภาษาไทยพร้อมต่อท้ายด้วยรายการคำกระตุ้น ตามแบบเดียวกับตัวที่มีอยู่แล้ว
3. เพิ่มชื่อลงในแถวที่เหมาะสมของ `hooks/skill-routing.yaml` และลงทะเบียนในทะเบียนความรู้ด้าน product
   ของไฟล์ `agents/solution-knowledge-agent.md`

**ข้อสี่ที่ต้องทำเมื่อเครื่องนี้ใช้ระบบเชื่อมโยงไฟล์** ตรวจก่อนด้วย `ls -l ~/.claude/skills | head -3`
ถ้าบรรทัดขึ้นต้นด้วยตัวอักษร `l` และมีเครื่องหมาย `->` ชี้กลับมาที่คลังโค้ดนี้ แปลว่าใช้ระบบเชื่อมโยง
ให้สร้างทางลัดของ skill ใหม่ด้วยคำสั่งนี้ (แทน `<ชื่อ skill>` ด้วยชื่อโฟลเดอร์):

```
ln -sfn "$(pwd)/plugins/ice-b2b-sales/skills/<ชื่อ skill>/" ~/.claude/skills/<ชื่อ skill>
```

จากนั้นรันชุดทดสอบเพื่อยืนยันว่าตารางเส้นทางยังชี้ไปหา skill ที่มีอยู่จริงครบทุกตัว
ขั้นนี้เป็นส่วนหนึ่งของงานปกติ ไม่ใช่ทางเลือก เพราะตารางที่อ้างถึง skill ที่หาไม่เจอจะทำให้ทั้งระบบสะดุด:

```
python3 hooks/tests/test_router.py
```

**เกณฑ์เลือกแถวใน `hooks/skill-routing.yaml`** ให้ดูว่างานที่ skill ใหม่รับใช้เป็นงานประเภทใดตามคำอธิบาย
ในหัวข้อท้ายไฟล์นี้ แล้วใส่ลงแถวนั้น ถ้า skill หนึ่งตัวรับใช้ทั้งงานเขียนสคริปต์และงานจัดโครงสร้างโครงการ
ให้ใส่ทั้งสองแถวได้ เพราะระบบรวมผลของทุกแถวที่ตรงเข้าด้วยกัน ไม่ได้เลือกเพียงแถวเดียว

**เมื่อแก้เสร็จ** ให้ปรับเลขรุ่นและวันที่ที่หัวไฟล์นี้ พร้อมเขียนสั้น ๆ ว่าแก้อะไร แล้วจึงบันทึกเข้าคลังโค้ด

## จุดที่ระบบพา agent มาเจอ skill เหล่านี้

ตารางเส้นทาง `hooks/skill-routing.yaml` มีสามแถวที่เกี่ยวข้อง แถว `product-netsuite` เป็นร่มใหญ่ที่ดัง
ทุกครั้งที่เอ่ยชื่อ NetSuite แถว `netsuite-development` ดังเมื่องานพูดถึงการเขียนสคริปต์ และแถว
`netsuite-sdf` ดังเมื่องานพูดถึงการจัดโครงสร้างและติดตั้งโครงการ ทั้งสามแถวตั้งเป็นคำแนะนำ ไม่ใช่
เงื่อนไขบังคับ เพราะ skill กลุ่มนี้ใหญ่มาก การบังคับโหลดเมื่อมีคนเอ่ยชื่อผ่าน ๆ จะกินบริบทโดยไม่จำเป็น

agent ที่เป็นเจ้าของเรื่องคือ `solution-knowledge-agent` (ชื่อเล่น เทพ) ซึ่งมีรายชื่อ skill ทั้ง 10 ตัว
อยู่ในทะเบียนความรู้ด้าน product ในไฟล์ของตัวเอง พร้อมคำสั่งว่าให้เลือกเปิดตามแถวในตารางเส้นทาง
ไม่ใช่เปิดทั้งชุดพร้อมกัน เพราะรวมกันแล้วหลายแสนตัวอักษร
