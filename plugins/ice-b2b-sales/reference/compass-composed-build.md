# Compass.Next — Composed Build (CB): วิธีสร้างงานใหญ่เป็นหน่วยย่อยแล้วประกอบ (ย้ายมาจากไฟล์กัปตัน §5 เมื่อ 2026.09.05)

> **Version:** V01R01 | **Date:** 2026.09.05 | **ใช้โดย:** กัปตัน (`iCE-Compass-Next`) ในขั้น D-P3 BUILD ของ DOC-PIPELINE เมื่อเข้าเงื่อนไขเปิด CB
> **ไฟล์นี้ใช้ทำอะไร:** อธิบายครบว่า CB เปิดเมื่อไหร่ มี 5 phase อะไร แบ่งหน่วยอย่างไร ใครตรวจแต่ละหน่วย และเพดานรอบต่อหน่วย · ไฟล์กัปตันเหลือเพียงเงื่อนไขเปิดและ pointer มาที่นี่
> **เงื่อนไขเปิด CB:** deck มากกว่า 10 สไลด์ หรือ proposal ตั้งแต่ 2 บทขึ้นไป · deck ไม่เกิน 10 และน้อยกว่า 2 บท = ไม่ใช้ CB (build รวดเดียว)
> **นิยามที่ไฟล์นี้ใช้:** ② = `sales-process-agent` (ยอดนักขาย) · ③ = `solution-knowledge-agent` (เทพ ผู้ถืออำนาจตัดสินข้อเท็จจริง FACT) · ⑤ = `qa-master-agent` (อริส) · **หน่วย (unit)** = ส่วนย่อยของงานที่ตรวจแยกได้ เช่น สไลด์หนึ่งหน้า หรือบทหนึ่งบท · **N** = จำนวนหน่วยทั้งงาน · **PUL** = เพดานรอบแก้ต่อหน่วย (ค่าอยู่ตาราง CONTROL LIMITS ไฟล์กัปตัน §6: Fast=1 · Full=2 · Submit=3) · **CHAIN-ROUND** = เพดานรอบวนทั้งงาน (ไฟล์เดียวกัน) · **frame_ref** = โครงรวมที่ล็อกไว้ใน Phase 1 ให้ทุกหน่วยอ้าง · **section_pack / cb_unit_spec** = ช่องในซองคำสั่งที่ส่งให้ specialist (โครงเต็มที่ `reference/compass-briefing-pack.md`) · **Hard QA Gate / Producer≠Checker** = ไฟล์ทุกชิ้นต้องผ่านอริสในบริบทแยกจากผู้สร้าง (ไฟล์กัปตัน S5)

## 5 Phase — เดินตามลำดับ

```
Phase 0 FRAME     กำหนดกรอบงาน ผู้อ่าน และข้อความหลัก
Phase 1 OVERALL   หารือโครงทั้งงานกับ ③ ก่อน (ห้ามแบ่งเป็นชุด ห้ามข้าม) → ได้ outline และล็อก frame_ref
Phase 2 PER-UNIT  ร่างทีละหน่วย + ผู้ตรวจหนึ่งคนต่อหน่วย
Phase 3 PREVIEW   build หน่วยนั้น → ตรวจเทียบกรอบ → แก้ได้ไม่เกิน PUL → เกินให้ยกระดับ (ก ยอมรับตามสภาพ / ข เปลี่ยนทิศ / ค ข้ามหน่วยนี้)
Phase 4 BUILD-ONCE ทุกหน่วยผ่านแล้วจึง build รวมจาก unit-spec ทั้งชุดครั้งเดียว — ห้ามเอา preview มาเย็บต่อกัน
Phase 5 FINAL     ตรวจไฟล์รวมชิ้นเดียวกัน · ผ่าน → ส่งมอบ
```

## กติกาประกอบ

- **Granularity Ladder (ขนาดหน่วยตาม N):** N ≤ 12 ตรวจรายหน่วยทุกหน่วย · N 13-30 ตรวจเป็นชุดต่อ section (ไม่เกิน 6 หน่วยต่อชุด) · N > 30 ใช้ SAMPLE-FRAME คือตรวจตัวแทน 1 หน่วยต่อ section · Phase 1 ห้ามแบ่งชุดไม่ว่า N เท่าใด
- **ALWAYS-DRILL (ไม่เกิน 8 หน่วย):** หน่วยที่ผูกข้อผูกพัน (ราคา · man-day · การตอบ TOR · executive summary) ต้องตรวจเดี่ยวเสมอแม้ N ใหญ่
- **Reviewer Router (ผู้ตรวจหนึ่งคนต่อหน่วย · คนที่สองเฉพาะเมื่อไม่ผ่าน):** ③ เป็นค่าเริ่มต้นและถืออำนาจตัดสินข้อเท็จจริง · ② ตรวจหน่วยเชิงพาณิชย์ (③ ยังตรวจข้อเท็จจริงทับ) · Codex ใช้เมื่อหน่วยนั้นมีข้อโต้แย้งหรือเดิมพันสูง · OpenRouter ใช้เมื่อต้องการมุมผู้อ่านสมมติ (CFO / CIO) · ทุกกรณีรวมเป็นคำตัดสินเดียวต่อหน่วย
- **การย่อตามโหมด:** Fast = Phase 0 + Phase 1 (③ หนึ่งรอบ) + BUILD-ONCE + FINAL หนึ่งรอบ (ข้าม Phase 2-3 ยกเว้นหน่วย ALWAYS-DRILL) · Full และ Submit เดินครบ 5 phase
- **สิ่งที่ CB ไม่ยกเว้น:** Hard QA Gate และ Producer≠Checker ยังบังคับ · unit-spec ส่งผ่านช่อง `cb_unit_spec` ใน section_pack
- **การนับรอบเมื่อต้องกลับไปแก้กรอบ (Interaction กับ CONTROL LIMITS):** กลับไปตรวจกรอบใหม่ (frame-recheck) แล้วเข้า Phase 1 อีกครั้ง = ใช้ CHAIN-ROUND ไป 1 และ reset PUL ของทุกหน่วย · กลับไปแก้หน่วยเดิมไม่ reset PUL · เปลี่ยนกรอบทั้งงานทำได้ 1 ครั้งต่อการรัน · หน่วยที่ชนเพดาน PUL เกินหนึ่งในสามของทั้งหมด = หยุดทั้งงานแล้วตรวจกรอบใหม่ (frame-recheck) ก่อน
