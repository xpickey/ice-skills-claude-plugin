## 1. วิธีการทำงานร่วมกันระหว่าง user กับ agent — อ่านก่อนแตะไฟล์ใด ๆ

**user แก้ไขไฟล์ผลงานด้วยตัวเองเป็นเรื่องปกติหลังจากที่ agent สร้างเสร็จ** เพราะ user เป็นผู้เข้าใจเรื่องราวและสิ่งที่จะนำเสนอลูกค้าดีที่สุด ดังนั้นไฟล์ที่อยู่บนดิสก์คือความจริงของงานเสมอ ไม่ใช่ไฟล์ spec ไม่ใช่สคริปต์ที่เคยสร้างไฟล์นั้น และไม่ใช่สิ่งที่จำได้จากการสนทนาครั้งก่อน

เมื่อจะทำงานต่อกับ artifact ที่มีอยู่แล้ว ต้องทำสามขั้นนี้ตามลำดับก่อนเริ่มงานเสมอ

1. ค้นหารุ่นล่าสุดของ artifact นั้นจากโฟลเดอร์จริง แล้วเปิดอ่านเนื้อหาไฟล์รุ่นนั้น
2. เทียบเนื้อหาที่อ่านได้กับ spec หรือรุ่นที่ตัวเองเคยสร้างไว้ เพื่อหาว่ามีจุดใดที่ user แก้ไขเพิ่มเติม แล้วปรับ spec ให้ตรงกับไฟล์จริง
3. เริ่มทำงานตามที่ได้รับมอบหมาย โดยรักษาการแก้ไขของ user ไว้ทุกจุด

❌ ตัวอย่างที่ผิด: นำสคริปต์ที่เคยสร้างเอกสารรุ่นก่อนมารันใหม่เพื่อสร้างรุ่นถัดไป โดยไม่เปิดดูไฟล์ปัจจุบัน ผลคือทุกอย่างที่ user แก้ไขด้วยมือหายไปทั้งหมด
✅ ตัวอย่างที่ถูก: เปิดไฟล์รุ่นล่าสุดอ่านก่อน พบว่า user แก้หัวข้อหน้าที่ห้าและเปลี่ยนตัวเลขในหน้าที่เก้า จึงบันทึกการแก้ทั้งสองจุดเข้า spec แล้วจึงสร้างรุ่นใหม่ที่มีทั้งการแก้ของ user และงานใหม่ที่ได้รับมอบหมาย

## 3. กติกาการเก็บรุ่นเก่า

**เมื่อบันทึกรุ่นใหม่ของ artifact ใด ให้ย้ายรุ่นก่อนหน้าของ artifact ชิ้นเดียวกันนั้นเข้าโฟลเดอร์ `_archive/` ของสายนั้น ภายในขั้นตอนเดียวกับการบันทึก** การย้ายต้องจำกัดอยู่เฉพาะรุ่นก่อนหน้าของไฟล์ชิ้นเดียวกันเท่านั้น **ห้ามย้ายหรือลบไฟล์อื่นใดเกินกว่านี้** ไม่ว่าจะเห็นว่าไฟล์นั้นดูเก่าหรือดูไม่จำเป็นก็ตาม

❌ ตัวอย่างที่ผิดแบบที่หนึ่ง: สร้างรุ่นใหม่แล้วปล่อยรุ่นเก่าไว้ที่เดิม ทำให้โฟลเดอร์มีหลายรุ่นปนกันจนไม่รู้ว่ารุ่นใดคือรุ่นที่ใช้งาน
❌ ตัวอย่างที่ผิดแบบที่สอง: ถือโอกาสย้ายไฟล์อื่นที่คิดว่าไม่ใช้แล้วเข้า `_archive/` ไปด้วย เหตุการณ์จริงคือ user ต้องย้ายไฟล์กลับคืนด้วยตัวเองสิบสองไฟล์
✅ ตัวอย่างที่ถูก: บันทึก `รายงาน_V01R08_2026.08.26.pptx` พร้อมกับย้าย `รายงาน_V01R07_2026.08.25.pptx` เข้า `_archive/` ในคำสั่งเดียวกัน โดยไม่แตะไฟล์อื่นเลย
