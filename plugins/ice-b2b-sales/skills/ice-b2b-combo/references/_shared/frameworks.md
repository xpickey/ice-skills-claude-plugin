# Shared — กรอบคิดวิเคราะห์ (Thinking Frameworks)

> กรอบวิเคราะห์ที่ใช้ร่วมหลายงาน (strategic-thinking, solution-selling, design-thinking, business case).
> เก็บที่เดียว — reference อื่นชี้มา. ใช้เป็น "วิธีคิดในใจ" — **ไม่ name-drop ชื่อ framework ในผลงานลูกค้า**
> (ใช้กรอบได้ แต่เขียน output เป็นภาษาธุรกิจปกติ ไม่อ้างชื่อ methodology/บริษัทที่ปรึกษา).

---

## 1. MECE (แยกประเด็นไม่ทับ ไม่ขาด)

แตกปัญหาเป็นกลุ่มย่อยที่ **ไม่ซ้อนกัน (Mutually Exclusive)** และ **ครบไม่มีตก (Collectively Exhaustive)**.
- ใช้เมื่อ: จัดโครง proposal, แตก scope, แยก stakeholder, list ความเสี่ยง.
- เช็ค: มีอะไรนับซ้ำ 2 กลุ่มไหม? · มีอะไรตกหล่นไม่อยู่กลุ่มไหนไหม?

## 2. Pyramid (สรุปก่อน เหตุผลตาม)

เขียน/พูดแบบ **ข้อสรุปขึ้นก่อน** แล้วค่อยตามด้วยเหตุผลสนับสนุนเป็นชั้น.
- ใช้เมื่อ: executive summary, board paper, การนำเสนอผู้บริหาร (เวลาน้อย ต้องรู้คำตอบก่อน).
- โครง: ข้อสรุป → 3 เหตุผลหลัก → หลักฐานใต้แต่ละเหตุผล.

## 3. Issue Tree (แตกคำถามเป็นต้นไม้)

แตกคำถามใหญ่ → คำถามย่อย → ย่อยอีก จนตอบได้.
- ใช้เมื่อ: วิเคราะห์ปัญหาซับซ้อน, หา root cause, วาง discovery.

## 4. Value Chain / As-Is → To-Be

map กระบวนการปัจจุบัน (As-Is) → สิ่งที่ควรเป็น (To-Be) → ช่องว่าง = สิ่งที่ solution เติม.
- ใช้เมื่อ: fit-gap, business case, demo design (โชว์ To-Be).
- ช่องว่าง (gap) แต่ละจุด = 1 เหตุผลซื้อ (ผูก why-stack.md).

## 5. Cost-Benefit / ROI frame

- ต้นทุน: license + implementation + change management + ต้นทุนแฝง.
- ผลตอบแทน: ประหยัด + รายได้เพิ่ม + ความเสี่ยงที่ลด.
- payback period = ต้นทุน ÷ ผลตอบแทนต่อปี.
- **ตัวเลขทุกตัวต้องมีที่มา** (ดู know.md FACT-gate) — payback ที่กุ = อันตราย.

## กฎการใช้ (สำคัญ)

- **กรอบอยู่ในหัว ผลงานเป็นภาษาธุรกิจ** — ลูกค้าเห็น proposal ที่เรียบเรียงดี ไม่ใช่ศัพท์ framework.
- **ไม่อ้างชื่อ** McKinsey/BCG/Big Four หรือชื่อ methodology ในเอกสารลูกค้า — แสดงความเป็นมืออาชีพผ่านคุณภาพเนื้อหา.
- เลือกกรอบให้พอดีงาน — ไม่ต้องใช้ทุกกรอบทุกครั้ง.
