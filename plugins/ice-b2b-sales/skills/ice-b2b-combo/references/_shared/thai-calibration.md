# Shared — Thai Market Calibration (ปรับภาษา/มารยาท/บริบทไทย)

> การปรับโทน ภาษา และบริบทให้เหมาะตลาดไทย — ใช้ร่วมหลายงาน (questioning, relationship-management,
> proposal, gov work). เก็บที่เดียว — reference อื่นชี้มา. ใช้ทุก stage ที่มีปฏิสัมพันธ์กับลูกค้าไทย.

---

## 1. Register / ระดับภาษา

- **ลูกค้าองค์กรไทย** — สุภาพ เป็นทางการ แต่ไม่แข็งจนห่างเหิน · ใช้ "ครับ/ค่ะ" เหมาะกาลเทศะ · เลี่ยงคำห้วน.
- **ภาครัฐ/รัฐวิสาหกิจ** — ทางการสูง · เคารพลำดับชั้น · อ้างระเบียบ/กฎหมายให้ถูกต้อง (ดู domain gov).
- **เอกชน/SME** — กระชับ เน้นผลลัพธ์ธุรกิจ · ตรงประเด็นกว่าภาครัฐได้.

## 2. คำถามเชิงลึกแบบไม่เสียมารยาท

ไทยไม่นิยมถามตรง ๆ เรื่องงบ/การเมืองภายใน — ทำให้นุ่มขึ้น:
- ❌ "งบเท่าไหร่" → ✅ "พอจะมีกรอบงบประมาณคร่าว ๆ ที่วางไว้ไหมครับ เพื่อผมจะเสนอให้พอดี"
- ❌ "ใครตัดสินใจ" → ✅ "นอกจากทีมที่คุยวันนี้ มีท่านอื่นที่ควรให้ข้อมูลประกอบการพิจารณาไหมครับ"

## 3. ความสัมพันธ์ก่อนธุรกรรม

- ไทยให้น้ำหนัก "ความไว้ใจ + ความสัมพันธ์" สูง — อย่ารีบปิดการขายก่อนสร้างความสัมพันธ์.
- ผู้บริหารระดับสูงมักเข้ามาช่วงตัดสินใจ ไม่ใช่ช่วงแรก — เคารพลำดับ.
- การพบหน้า/มื้ออาหารมีน้ำหนักจริงในวัฒนธรรมธุรกิจไทย.

## 4. รัฐวิสาหกิจ (SOE) / ภาครัฐ overlay

- ผูกกับ **ปีงบประมาณ** (ต.ค.–ก.ย.) — timeline ต้องสอดคล้องรอบงบ.
- กระบวนการจัดซื้อตามระเบียบ — Paper Process ใน MEDDPICC สำคัญมาก (ดู `domain/govt-egp.md`).
- TOR เป็นหัวใจ — ตอบให้ comply ทุกข้อ + honest (ดู check.md D9).

## 5. เอกสาร bilingual

- ถามภาษา output ก่อนเสมอ (ไทย / อังกฤษ / สองภาษา) — ไม่เดา.
- ไทย+อังกฤษในไฟล์เดียว = ระวังฟอนต์ (ดู build-spec.md D1-D4).
- ศัพท์เทคนิค: คงภาษาอังกฤษได้ถ้าแปลไทยแล้วงงกว่า (เช่น "ERP", "Cloud") — อย่าแปลทื่อ ๆ จนเพี้ยน.

## กฎ

- ปรับ register ตามผู้รับ — ผู้บริหารต่างจากทีม technical ต่างจากภาครัฐ.
- positive wording (ดู route.md) + Thai politeness ไปด้วยกัน — สุภาพและบวก.
