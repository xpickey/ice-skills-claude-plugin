# Method — Relationship Management (บริหารความสัมพันธ์ลูกค้า ครบวงจร)

> บริหาร account ตลอด lifecycle: Prospect → Pursue → Onboard → Adopt → Expand → Renew → Advocate → Recover.
> ระดับ account (ไม่ใช่ระดับดีลเดียว). ใช้ช่วง Close → Onboard → QBR → Renew → Expand. เน้นความ "ทนทาน + เติบโต" ของความสัมพันธ์.
> Thai overlay + qualification อยู่ `_shared/` — ที่นี่เน้น "lifecycle motion + health + champion + renewal".

---

## Lifecycle 8 ขั้น

| ขั้น | โฟกัส |
|---|---|
| Prospect | ระบุ account เป้าหมาย |
| Pursue | ดีลแรก (ดู `method/solution-selling.md`) |
| Onboard | ส่งมอบ + value แรก |
| Adopt | ลูกค้าใช้จริง + เห็นผล |
| Expand | white-space → upsell/cross-sell |
| Renew | ต่อสัญญา |
| Advocate | ลูกค้าเป็น reference |
| Recover | กู้ความสัมพันธ์เมื่อมีปัญหา |

---

## 1. Stakeholder + Power Mapping

- map buying center: ใคร influence · ใคร decision · ใคร block.
- **power vs interest grid** — ดูแลคนที่ power สูง + interest สูงเป็นพิเศษ.
- **multi-threading** — อย่าผูกคนเดียว (เขาออก = account เสี่ยง). มีสาย ≥3 ระดับ/ฝ่าย.

## 2. Account Health Score

ให้คะแนนสุขภาพ account เป็นระยะ:
- **product adoption** — ใช้จริงแค่ไหน (login/feature usage).
- **value realized** — ได้ผลตามที่ขายไหม.
- **relationship depth** — มีกี่สาย · champion แข็งไหม.
- **commercial** — จ่ายตรงเวลา · ไม่มีสัญญาณ churn.
- 🔴 หลายตัว = เสี่ยง churn → เข้า Recover.

## 3. Champion Development

- **Champion ≠ Coach** — Champion มี power + เชียร์ + พร้อมสู้แทนเรา (ดู `_shared/meddpicc.md`).
- พัฒนา champion: ให้ win ภายใน (ช่วยเขาดูดีต่อนาย) · ติดอาวุธข้อมูล · ทดสอบ power จริง.
- **single-threaded = ความเสี่ยง** — champion ออก ต้องมีสำรอง.

## 4. QBR / EBR cadence

- **QBR** (Quarterly Business Review) — ทบทวน value, adoption, roadmap กับ user/manager.
- **EBR** (Executive Business Review) — กับผู้บริหาร: value ที่ส่งมอบ + แผนต่อ + expansion.
- ใช้คำถาม value-realized + expansion-surfacing (ดู `method/questioning.md`).

## 5. Renewal + Expansion motion

- **เริ่ม renewal ล่วงหน้า** (ไม่ใช่เดือนสุดท้าย) — 90-120 วันก่อนหมดสัญญา.
- **white-space mapping** — module/process ที่ยังไม่ได้ขาย = โอกาส expand.
- **Why Stay** (ดู `_shared/why-stack.md`) — roadmap + ความสัมพันธ์ + expansion path.

## 6. Escalation + Recovery

- เมื่อมีปัญหา → ตอบเร็ว + โปร่งใส + แผนแก้ชัด (honest ไม่กลบ).
- ผู้บริหารทั้งสองฝั่งเข้ามาช่วย (executive sponsor).
- กู้ความสัมพันธ์ = โอกาสสร้างความไว้ใจที่ลึกขึ้น ถ้าจัดการดี.

## Thai / Government + SOE overlay

- **bunkhun (บุญคุณ)** — ความสัมพันธ์ระยะยาวมีน้ำหนักจริง · ดูแลต่อเนื่องไม่ใช่แค่ตอนขาย.
- **face** — escalation อย่าทำให้ลูกค้าเสียหน้า (โดยเฉพาะต่อหน้าทีมเขา).
- **ภาครัฐ/SOE:** renewal ผูกปีงบประมาณ + กระบวนการจัดซื้อ (ดู `domain/govt-egp.md`) · ผู้บริหารหมุนเวียนตามวาระ — map ใหม่เมื่อเปลี่ยนผู้บริหาร.
- **อบจ./รัฐวิสาหกิจ** — โครงสร้างอำนาจต่างเอกชน (board/วาระ) ดู `_shared/thai-calibration.md`.

> ระดับ account ไม่ใช่ดีลเดียว — มองยาว: ดีลแรกคือจุดเริ่ม ไม่ใช่จุดจบ.
