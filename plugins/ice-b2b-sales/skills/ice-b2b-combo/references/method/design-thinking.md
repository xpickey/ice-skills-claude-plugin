# Method — Design Thinking + Ideation (workshop / envisioning)

> 2 วินัยคู่กันสำหรับ pre-sales: **Design Thinking** (bottom-up, human-centered — "ควรสร้างอะไร เพื่อใคร พิสูจน์ยังไง")
> + **Strategic** (top-down — "เล่นที่ไหน ชนะยังไง") — เสริมกัน ไม่แทนกัน. ใช้ช่วง Discovery → Envisioning → Solution → Demo.
> Why-Invest/Now/Us อยู่ `_shared/why-stack.md` · กรอบคิดอยู่ `_shared/frameworks.md` — ที่นี่เน้น "workshop + ideation".
> **ผลิต ≥3 ทางเลือกพร้อม trade-off เสมอ.**

---

## เมื่อไหร่ใช้ Design Thinking vs Strategic (เช็คก่อน)

| ใช้ Design Thinking เมื่อ | ใช้ Strategic เมื่อ (ดู `method/strategic-thinking.md`) |
|---|---|
| discovery workshop / envisioning | account strategy / where-to-play |
| ออกแบบ solution / demo | competitive positioning |
| ideation / brainstorm | portfolio choice |
| value-case จาก user pain | market entry |

**บอกผู้ใช้เสมอ** ว่างานนี้ต้อง DT, Strategic, หรือทั้งคู่.

---

## Design Thinking flow (workshop)

1. **Empathy** — เข้าใจ user จริง (empathy map: เห็น/ได้ยิน/คิด/รู้สึก). อย่าเดา pain — ถาม (ดู `method/questioning.md` JTBD).
2. **Define** — ตกผลึกปัญหาเป็น 1 ประโยค "How Might We…".
3. **Ideate** — แตกไอเดียกว้าง (≥3 ทางเลือก) ก่อนตัด.
4. **Prototype** — ทำให้จับต้องได้ (mockup/demo flow/journey map).
5. **Test** — เอาให้ user ลอง → เก็บ feedback → วนปรับ.

---

## Workshop facilitation (จัด envisioning session)

- **เปิด:** ตั้ง objective + กติกา + ดึงทุกคนมีส่วนร่วม (ไทย: ผู้ใหญ่พูดก่อน — ดู `_shared/thai-calibration.md`).
- **divergent ก่อน convergent** — แตกไอเดียให้กว้างก่อน (ห้ามวิจารณ์) → แล้วค่อยคัด.
- **journey map** — วาด as-is journey → จุดเจ็บ → to-be journey (ผูก `_shared/frameworks.md` value-chain).
- **ปิด:** สรุปทางเลือก + next step + เจ้าภาพ.

## Ideation tools

| tool | ใช้ตอน |
|---|---|
| How-Might-We (HMW) | reframe ปัญหาเป็นโจทย์ออกแบบ |
| Crazy-8s / brainstorm | แตกไอเดียเร็ว ๆ |
| journey map | เห็น pain ตลอด process |
| 2×2 prioritization | คัดไอเดีย (impact × effort) |

## Value-case (เชื่อมไป business case)

หลัง workshop → ร้อยเป็น value-case: pain ที่เจอ → solution → ผลลัพธ์ (ตัวเงิน/ความเสี่ยงลด) → Why Invest/Now/Us.
- ตัวเลขมีที่มา (ดู `_capabilities/know.md` FACT-gate) — ไม่กุ ROI จาก workshop.
- ออกเป็น exec readout (Pyramid: ข้อสรุปนำ — ดู `_shared/frameworks.md`).

## Thai-market workshop

- **kreng-jai** ทำให้คนเงียบ — ใช้ technique เขียนก่อนพูด (sticky note) ให้ทุกคนมีเสียง.
- **hierarchy** — ผู้ใหญ่ comment ก่อนอาจปิดความเห็นคนอื่น → เก็บความเห็นเป็นลายลักษณ์ก่อน.
- **bilingual artifact** — workshop output ไทย/อังกฤษ ระวังฟอนต์ (ดู `_capabilities/build-spec.md`).

> ≥3 ทางเลือก + trade-off เสมอ → ส่งต่อไป business case / proposal.
