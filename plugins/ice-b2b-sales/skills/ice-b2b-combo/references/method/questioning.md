# Method — Questioning (ออกแบบคำถามที่ชนะดีล)

> วินัยการตั้งคำถามที่ชนะดีล enterprise software, ออกแบบ solution, รักษา account.
> ใช้ช่วง Discovery → Qualification → Solution → Demo → QBR → Renewal. คำถามคือทักษะ leverage สูงสุดในงานขาย enterprise.
> qualification scorecard อยู่ `_shared/meddpicc.md` — ที่นี่เน้น "การออกแบบ + ลำดับ + ถามนุ่มแบบไทย".

---

## 6-step workflow

### Step 1 — ยืนยัน context 5 อย่างก่อนออกคำถาม (ขาดอันไหน = ถาม)
- **Role:** AE (sales) · SC (pre-sales) · CSM (customer success)
- **Stage:** prospecting / discovery / qualification / solution / demo / RFP / negotiation / close / onboarding / QBR / renewal / expansion
- **Persona:** Economic Buyer (CFO/CEO) · Technical Buyer (CIO/IT) · User Buyer (Finance/Ops/HR head) · Champion
- **Process area:** Record-to-Report · Procure-to-Pay · Order-to-Cash · Hire-to-Retire · Treasury · Compliance · Analytics
- **Cultural context:** Thai (default) · APAC · Western · mixed → กำหนด register

### Step 2 — เลือกกรอบหลัก
- **SPIN** = แกน discovery (Situation → Problem → Implication → Need-Payoff)
- **Pain Funnel** = เจาะลึก pain ที่สำคัญสุด
- **Challenger** = 1 คำถาม reframe ที่ท้าทาย (มี research รองรับ)
- **5 Whys** = หา root cause เมื่อปัญหาคลุมเครือ
- **JTBD / Design-Thinking laddering** = solution workshop

### Step 3 — ร่างคำถาม 8-20 ข้อ
funnel: กว้าง→แคบ · อดีต→ปัจจุบัน→อนาคต · Situation→Problem→Implication→Need-Payoff.

### Step 4 — tag ทุกคำถาม
framework origin + target persona + purpose (เพื่อรู้ว่าคำถามนี้ทำงานอะไร).

### Step 5 — ปรับ register ไทย (สำคัญ)
คำถามที่ตรงเกินในวัฒนธรรมไทย → ทำให้นุ่ม + แนะว่าควรถามในห้องหรือ follow-up ส่วนตัว.

### Step 6 — ทำ meeting plan
opening move · ลำดับ · เตือน "เงียบ 3 วินาที" (ให้ลูกค้าคิด) · probing follow-up · MEDDPICC-refresh หลังประชุม · 1 คำถามเสี่ยงที่ควรถามแม้อึดอัด.

## SPIN funnel (แกน discovery)

| ชั้น | ถามอะไร | ตัวอย่าง |
|---|---|---|
| **S**ituation | สถานะปัจจุบัน | "ตอนนี้ใช้ระบบอะไรจัดการ [process]" |
| **P**roblem | ปัญหา | "ส่วนไหนของระบบเดิมที่ทำให้ทีมเสียเวลา" |
| **I**mplication | ผลกระทบ (ขยาย pain) | "ถ้าปิดงบช้า 1 สัปดาห์ กระทบการตัดสินใจผู้บริหารยังไง" |
| **N**eed-Payoff | คุณค่าถ้าแก้ได้ | "ถ้าปิดงบได้ใน 3 วัน จะเปลี่ยนอะไรในการบริหาร" |

**กุญแจ:** Implication คือชั้นที่ขยาย pain ให้ลูกค้าเห็นต้นทุนจริง — อย่ารีบข้ามไป pitch.

## ปรับ register ไทย — 4 มิติ

| มิติ | ความหมาย | ผลต่อคำถาม |
|---|---|---|
| **kreng-jai** | เกรงใจ ไม่อยากรบกวน | ถามนุ่ม ให้ทางเลือกไม่ตอบ |
| **face (นับหน้าถือตา)** | รักษาหน้า | ไม่ถามจี้จุดอ่อนต่อหน้าคนอื่น |
| **hierarchy (ผู้ใหญ่-ผู้น้อย)** | ลำดับชั้น | ถามผู้ใหญ่ต่างจากผู้น้อย |
| **bunkhun** | บุญคุณ/ความสัมพันธ์ | สร้างความสัมพันธ์ก่อนถามลึก |

**ตัวอย่างถามนุ่ม:**
- ❌ "งบเท่าไหร่" → ✅ "พอจะมีกรอบงบที่วางไว้คร่าว ๆ ไหมครับ เพื่อผมเสนอให้พอดี"
- ❌ "ใครตัดสินใจ" → ✅ "นอกจากทีมวันนี้ มีท่านอื่นที่ควรให้ข้อมูลประกอบไหมครับ"

> รายละเอียด Thai context เต็ม → `_shared/thai-calibration.md`

## คำถามตาม stage (เลือกใช้)

- **Prospecting:** 1 SPIN-Situation opener + 1 Challenger (มี research) + 1 Champion-surfacing
- **Discovery:** SPIN funnel เต็ม ต่อ process + Pain Funnel บน pain แรงสุด + 5-Whys ถ้าคลุมเครือ
- **Qualification (private):** MEDDPICC — ตัวไหน confidence <5/10 = agenda ครั้งหน้า (ดู `_shared/meddpicc.md`)
- **Solution workshop:** JTBD opener + How-Might-We + ladder why/what/how
- **Demo/Proof:** เปิดด้วย context-question + ปิดด้วย Need-Payoff
- **QBR/Renewal:** value-realized question + expansion-surfacing

> ทุกคำถามต้องมีจุดประสงค์ — ไม่ถามเพื่อถาม. คำถามคม = ดีลคืบ.
