# Web Research + Validation Protocol (tool-agnostic)

> วิธีค้นข้อมูลและตรวจความถูกต้องก่อนตอบ — **ไม่ผูกเครื่องมือตัวใดตัวหนึ่ง** (ใช้ web-search ที่มีในสภาพแวดล้อมนั้น
> ไม่ว่าจะเป็น built-in WebSearch, MCP, หรือ browser). โหลดจาก STEP 3 เมื่อต้องยืนยันข้อเท็จจริง.

---

## 1. เมื่อไหร่ต้องค้น (ไม่ใช่ทุกครั้ง)

ค้น web เมื่อข้อมูลเป็นอย่างใดอย่างหนึ่ง:
- **ASSUMPTION** (ดู know.md) ในจุดสำคัญ — ตัวเลข/ชื่อ/วันที่ที่ไม่มีแหล่ง.
- **version-specific** — feature/limit/pricing ของ product ที่ release/เปลี่ยนบ่อย.
- **กฎหมาย/ระเบียบ** — ฉบับ/มาตรา/วันบังคับใช้ (โดยเฉพาะไทย — แก้บ่อย).
- **ตัวเลขตลาด/คู่แข่ง** — market size, ส่วนแบ่ง, ข่าว vendor.

**ไม่ต้องค้น** เมื่อ: เป็นความรู้ method ทั่วไป (วิธี qualify, โครง proposal) ที่มั่นใจ + ไม่ใช่ fact เฉพาะ.

> **ถ้าสภาพแวดล้อมห้ามค้นเน็ตโดยไม่ขอ** (เช่น policy ผู้ใช้) → ขออนุญาตก่อนค้น หรือ flag ว่า "ข้อมูลนี้ควรยืนยันด้วยการค้น".

---

## 2. ขั้นตอนค้น + cross-check

1. **ค้น** ด้วยเครื่องมือที่มี — ตั้ง query เจาะจง (ชื่อ product + version + ปี).
2. **Cross-check ≥ 2 แหล่งอิสระ** — อย่าเชื่อแหล่งเดียว โดยเฉพาะเรื่องตัวเลข/กฎหมาย.
   - แหล่งทางการ > บล็อก/ฟอรัม (เอกสาร vendor, ราชกิจจาฯ, เว็บหน่วยงาน).
   - 2 แหล่งตรงกัน → confidence สูงขึ้น · ขัดกัน → ดูข้อ 3.
3. **Cite** — บอกผู้ใช้ว่าข้อมูลมาจากไหน + ณ วันที่ไหน ("ตาม [แหล่ง], ข้อมูล ณ [เดือน/ปี]").

---

## 3. เมื่อข้อมูลขัดกัน / ไม่เจอ

- **ขัดกัน** → **ไม่เลือกข้างเงียบ ๆ**. รายงานทั้ง 2 + บอกว่าอันไหนน่าเชื่อกว่าเพราะอะไร + แนะให้ผู้ใช้ยืนยันกับแหล่งทางการ.
- **ไม่เจอ** → **flag ไม่เดา**: "ไม่พบข้อมูลยืนยันเรื่องนี้ — ควรตรวจกับ [เอกสาร/หน่วยงาน] ก่อนนำไปใช้ในเอกสารลูกค้า".
- **เจอแต่เก่า** → บอกชัดว่าเป็นข้อมูล ณ ช่วงไหน + อาจมี update.

---

## 4. ผูกกับ confidence

หลังค้นเสร็จ ปรับ confidence (ดู know.md):
- 2+ แหล่งทางการตรงกัน → **high**.
- 1 แหล่ง หรือแหล่งรอง → **medium** + แนะตรวจเพิ่ม.
- ขัดกัน/ไม่เจอ → **low** + flag ชัด.

**high-stakes (ตัวเลขในสัญญา/proposal ที่ผูกพัน) + confidence < high** → เตือนผู้ใช้ให้ยืนยันก่อน commit.

---

## 5. Offline mode (ค้น web ไม่ได้ในสภาพแวดล้อมนั้น)

บาง runtime ห้ามค้นเน็ต/ไม่มีเครื่องมือค้น — ห้ามแกล้งทำเป็นค้นได้:
- ข้อเท็จจริงที่ต้องยืนยันแต่ค้นไม่ได้ → **mark `unverified`** + ห้าม claim เป็นข้อมูลสด/ปัจจุบัน.
- customer-facing → ระบุชัด "ข้อมูลนี้ยังไม่ได้ยืนยัน — ควรตรวจกับ [แหล่งทางการ] ก่อนใช้".
- ใช้ FACT/PATTERN/ASSUMPTION gate เข้มขึ้น (ดู `_capabilities/know.md`) — สิ่งที่เดา = ASSUMPTION ชัดเจน.

## 6. กฎทอง

> ค้นเพื่อ **ยืนยัน** ไม่ใช่เพื่อ **หาเหตุผลให้สิ่งที่เดาไว้**. ถ้าค้นแล้วพบว่าที่คิดไว้ผิด — แก้ตามข้อมูล ไม่ใช่ดันทุรัง.
> เป้าหมายคือความถูกต้อง ไม่ใช่ความเร็ว — ข้อมูลผิดในเอกสารลูกค้าเสียหายกว่าตอบช้า.
