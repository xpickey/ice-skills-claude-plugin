## 1. โครงข้อเสนอของทั้งชุด (ทำก่อนออกแบบรายหน้า)

ก่อนคิดว่าแต่ละหน้าหน้าตาเป็นอย่างไร ให้ตัดสินก่อนว่าทั้งชุดเดินเรื่องอย่างไร โครงนี้มีสามส่วน

**(ก) สลับหน้าความเชื่อกับหน้าหลักฐาน** วางแกนเรื่องตามลำดับคำถามที่ลูกค้าถามในใจ คือ ทำไมต้องเปลี่ยน · ทำไมต้องเปลี่ยนตอนนี้ · ทำไมต้องลงทุน · ทำไมต้องเป็นเรา · ทำไมต้องอยู่กับเราต่อ ทุกหน้าความเชื่อต้องมีหน้าหลักฐานตามติดทันที การวางหน้าความเชื่อติดกันสามหน้าทำให้คณะกรรมการลดขอบเขตงานลง เพราะฟังดูเป็นความฝันที่ยังไม่มีวิธีทำ

**(ข) น้ำหนักของภาพอนาคตเทียบกับหลักฐาน เปลี่ยนตามขั้นการขาย**

| ขั้นการขาย | น้ำหนักภาพอนาคต | เหตุผล |
|---|---|---|
| ออกแบบทางออก | สูง | ผู้ฟังยังสำรวจทางเลือก การเสนอมุมมองใหม่ให้ผลตอบแทนสูงที่สุดในช่วงนี้ `[ข้อมูลจากงานวิจัยฝ่ายจัดซื้อ — ยังไม่ได้ยืนยันตัวเลข]` |
| ยื่นข้อเสนอ | ปานกลาง โดยให้หลักฐานนำ | ผู้ฟังกำลังเทียบข้อกำหนดกับข้อเสนอ การลดความเสี่ยงให้คณะกรรมการสำคัญกว่าการขายภาพ `[ยังไม่ได้ยืนยันตัวเลข]` |
| เจรจาและปิด | หลักฐานนำ | ภาพอนาคตจบไปแล้ว ช่วงนี้เน้นความเป็นไปได้จริงและเงื่อนไขทางการค้า เพื่อลดความลังเลของผู้ตัดสินใจ |

**(ค) ภาพอนาคตต้องเป็นของลูกค้ารายนี้จริง** หน้าที่แสดงสถานะปลายทางต้องใช้ข้อมูลของลูกค้าเอง ไม่ใช่ภาพสาธิตทั่วไป ข้อมูลที่ยังไม่มีให้กำกับว่าต้องได้จาก user ตามหัวข้อข้อห้ามกุข้อมูลของสกิลหลัก

*ถ้อยคำสองเสียง (ภาพฝันคู่กับความจริง) เป็นเรื่องของสกิล `b2b-why-thinking` โหมดที่ 3 ซึ่งเป็นบ้านเดียวของเรื่องนั้น ที่ `~/.claude/skills/b2b-why-thinking/references/pitch-belief-card.md` — ไฟล์นี้จัดเฉพาะลำดับและน้ำหนัก ไม่ได้เขียนถ้อยคำ*

## 2. การผสมแม่แบบสำเร็จรูปกับเนื้อหาจริง

การผสมไม่ได้แปลว่ายัดเนื้อหาลงช่องของแม่แบบให้ครบ ผลของการทำแบบนั้นคือช่องว่างที่ยังเขียนว่า SUBTITLE ค้างอยู่ และตัวอักษรล้นกรอบ การผสมที่ถูกคือหยิบ **ลักษณะของโครง** มาใช้ เช่น แผนภาพแตกกิ่งเพื่อตัดสินใจ ตารางเปรียบเทียบสองคอลัมน์ กรวย พีระมิด เส้นเวลา หรือเมทริกซ์ แล้วสร้าง object ตามจำนวนเนื้อหาจริง

**ลำดับการทำเมื่อเปิดแม่แบบ**

1. **ดูลักษณะ** เปิดไฟล์แม่แบบแล้วดูว่าเป็นโครงแบบใด และมีลักษณะทางสายตาอย่างไร (มุมมนหรือมุมคม ความหนาเส้น ระยะห่าง) ไม่ต้องไล่ดูรูปทรงทีละชิ้น จับลักษณะรวมพอ
2. **นับเนื้อหา** โครงเนื้อหาที่จะลงมีกี่กิ่ง กี่ใบ กี่รายการ เช่น สามทางเลือก คูณสองรายละเอียด เท่ากับสามกิ่ง หกใบ
3. **สร้างเท่าเนื้อหา** สร้าง object ตามจำนวนที่นับได้ ไม่ใช่ตามจำนวนช่องของแม่แบบ · เนื้อหาน้อยกว่าช่อง ให้สร้างเท่าเนื้อหาแล้วจัดวางใหม่ให้เต็มพื้นที่อย่างสมดุล · เนื้อหามากกว่าช่อง ให้ลดขนาด object และขนาดตัวอักษรลงให้พอดี ถ้ายังเกินจริงให้แยกเป็นสองหน้าแล้วแจ้ง user
4. **ลงลักษณะทางสายตา** ใช้ลักษณะของแม่แบบเป็นแนว แต่ใช้สีตาม Corporate Identity ที่ระบุใน content-spec และใช้ฟอนต์ตาม font_strategy ที่ `b2b-slide-designer` ส่งมา
5. **จัดขนาดตัวอักษรให้พอดี** ข้อความไทยยาวกว่าอังกฤษในเนื้อความเดียวกัน ให้เปิดการตัดบรรทัดและลดขนาดตามลำดับชั้น เช่น หัวโครง 14 · หัวข้อย่อย 11 · รายละเอียด 9 พอยต์ · ตั้งฟอนต์ไทยให้กล่องข้อความทุกกล่อง ไม่ใช่เฉพาะกล่องที่เพิ่งแทนที่ เพราะกล่องเดิมของแม่แบบจะค้างฟอนต์ขนาดใหญ่ไว้
6. **ตรวจก่อนไปต่อ** เปิดดูภาพที่ได้จริง ต้องไม่มีคำว่า TITLE หรือ SUBTITLE ค้าง ไม่มีข้อความล้นกรอบ และจำนวน object เท่ากับจำนวนเนื้อหา

**กฎจำนวนไม่ตรงกัน** แม่แบบเป็นแรงบันดาลใจของลักษณะ ไม่ใช่กรอบตายตัว ช่องที่เหลือให้ลบ ช่องที่ขาดให้เพิ่ม การปล่อยช่องว่างของแม่แบบค้างไว้บนงานที่ส่งลูกค้าเป็นข้อบกพร่องที่ผู้ตรวจตีกลับ

**ทางออกเมื่อแม่แบบซับซ้อนเกินไป** แม่แบบที่มีรูปทรงซ้อนกันเป็นร้อยชิ้นและโครงไม่ตรงกับเนื้อหาเลย ให้วาดใหม่ตามลักษณะนั้นด้วย python-pptx ตาม content-spec ซึ่งเร็วกว่าและสะอาดกว่าการแกะแม่แบบ

❌ เปิดแม่แบบเมทริกซ์ 9 ช่อง แล้วเติมเนื้อหาที่มีจริง 4 รายการ ปล่อยอีก 5 ช่องว่างไว้พร้อมคำว่า SUBTITLE
✅ เปิดแม่แบบเดียวกัน เห็นว่าเป็นเมทริกซ์ แล้วสร้างเมทริกซ์ 4 ช่องขนาดใหญ่ขึ้นให้เต็มพื้นที่ ใช้สีและมุมมนแบบเดียวกับแม่แบบ

## 3. ตัวอย่างให้เลือกก่อนสร้างเต็ม

หลักคือไม่สร้างเอกสารทั้งชุดเสร็จแล้วจึงรู้ว่า user ไม่ชอบแนวนั้น ให้ทำตัวอย่างสั้น ๆ ให้เลือกและยืนยันก่อน

1. สร้างตัวอย่าง 2 ถึง 3 แนวที่ต่างกันจริง เช่น แผนภาพแตกกิ่ง เทียบกับ เมทริกซ์ เทียบกับ ผังลำดับงาน แต่ละแนวสร้างเป็นไฟล์ .pptx หน้าเดียวตามวิธีในหัวข้อ 2 แล้วแปลงเป็นภาพ PNG
2. แสดงภาพทั้งชุดให้ user ดู พร้อมอธิบายสั้น ๆ ว่าแต่ละแนวเหมาะกับสถานการณ์ใด
3. รอให้ user เลือกหนึ่งแนวหรือขอปรับ
4. สร้างเอกสารเต็มเฉพาะแนวที่เลือก

ใช้วิธีนี้กับงานที่ยังไม่ชัดว่าควรใช้แนวใด งานที่แนวชัดอยู่แล้วให้ข้ามไปสร้างเต็มได้เลยเพื่อไม่เสียเวลา ตัวอย่างเป็นภาพ PNG เป็นค่าเริ่มต้นเพราะเร็วและเห็นของจริง ถ้า user ขอแบบกดดูได้จึงทำเป็น HTML

## 4. ให้คะแนนงานตัวเองก่อนปล่อย (6 แกน)

ทำหลังจากได้ content-spec หรือตัวอย่างแล้ว แต่ก่อนสร้างเต็มหรือก่อนส่งงาน ให้คะแนนตัวเอง 6 แกน แกนละ 1 ถึง 5 คะแนน

| แกน | คำถามที่ใช้ตัดสิน | 1 คะแนน | 5 คะแนน |
|---|---|---|---|
| จุดยืนของงาน | งานชิ้นนี้มีมุมมองของตัวเองไหม และเดินตามโครงข้อเสนอในหัวข้อ 1 หรือไม่ | สวยลอย ๆ ไม่มีจุดยืน | มีจุดยืนและเหตุผลของการออกแบบ |
| ลำดับสายตา | สายตาไปที่จุดสำคัญก่อนไหม | ทุกอย่างเด่นเท่ากัน | ลำดับชัดเจน |
| ความเนี้ยบ | มีองค์ประกอบค้างหรือเพี้ยนไหม | มีช่องว่างค้าง ขอบเบี้ยว | เรียบร้อยทุกจุด |
| ความเฉพาะเจาะจง | ตรงกับเนื้อหา แบรนด์ และอุตสาหกรรมของลูกค้ารายนี้ไหม | เหมือนแม่แบบสำเร็จรูป | ตรงกับ Corporate Identity และเนื้อหาจริง |
| ความยับยั้ง | ตัดส่วนเกินออกหรือยัดทุกอย่างลงไป | แน่นจนรก | พอดี มีพื้นที่ว่าง |
| ความหลากหลาย | สไลด์ต่าง ๆ ใช้แม่แบบเดียวซ้ำรัวไหม | ทุกหน้าหน้าตาเดียวกัน | หลากหลายแต่กลมกลืน |

**วิธีใช้คะแนน** บันทึกคะแนนทั้ง 6 แกนไว้ในหมายเหตุของ content-spec · แกนใดได้ต่ำกว่า 3 ให้แก้ก่อนปล่อยงาน · เพดานจำนวนรอบแก้อยู่ที่ขั้นที่ 8 ของ `SKILL.md` ซึ่งเป็นบ้านของรอบตรวจ · ตัวอย่างที่ส่งให้ user ดูตามหัวข้อ 3 ต้องผ่านการให้คะแนนนี้ก่อนเสมอ

ตัวตรวจด้านสายตาที่จับร่องรอยงานที่ดูเหมือนเครื่องทำ อยู่ที่สกิล `b2b-slide-designer` หัวข้อ 4.8 และหัวข้อ 4.10 ซึ่งเป็นบ้านของเรื่องนั้น
