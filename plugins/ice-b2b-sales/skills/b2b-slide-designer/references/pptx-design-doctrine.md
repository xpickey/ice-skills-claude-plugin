# แนวทางการทำสไลด์ของ iCE — กฎประจำที่ใช้กับทุก deck ไม่ว่าใช้แม่แบบใด

> **Version:** V01R01 | **Date:** 2026.09.05 | จัดทำตามคำสั่งของ user จากการวิเคราะห์ log สิงหาคม–กันยายน 2026
> **ไฟล์นี้ใช้ทำอะไร:** เป็นบ้านเดียวของกฎออกแบบสไลด์ที่ user ต้องพิมพ์สั่งซ้ำมาตลอด (infographic และ icon 46 ครั้ง · color code 41 ครั้ง · ภาษา 38 ครั้ง) เพื่อให้ไม่ต้องสั่งอีก
> **ใครใช้:** ผู้ที่ออกแบบหรือสร้างสไลด์ทุกคน (skill b2b-slide-designer และ b2b-presentation-creator) และผู้ตรวจคุณภาพ (อริส) · hook ด่านก่อนคิดฉีดไฟล์นี้เข้า context ทุกครั้งที่มีงานสไลด์
> **ขอบเขต:** ใช้กับสไลด์ทุกชุดที่ลูกค้าหรือผู้บริหารจะเห็น ไม่ว่าจะใช้แม่แบบของ iCE แม่แบบของลูกค้า หรือแม่แบบทั่วไป — **ไม่ใช่เรื่องเดียวกับ "iCE Super Template" (แม่แบบลายทอง)** ซึ่งยังใช้เฉพาะเมื่อ user เอ่ยชื่อ

## กฎ 6 ข้อ

**ข้อ 1 — ภาษาเป็นภาษาธุรกิจ ไม่บรรยาย** ข้อความบนสไลด์ต้องเป็นภาษาที่ผู้บริหารอ่านแล้วเข้าใจทันที ไม่ใช้สำนวนโอ้อวดหรือประโยคเยิ่นเย้อ ข้อความที่ยาวเกินสองบรรทัดให้แตกเป็น bullet ทีละประเด็น กติกาภาษาฉบับเต็มอยู่ที่ `~/.claude/agents/reference/language-register.md`

**ข้อ 2 — ทุกหน้าเนื้อหาต้องมีภาพที่ช่วยให้เข้าใจ** หน้าเนื้อหาทุกหน้าต้องมี infographic หรือแผนภาพอย่างน้อยหนึ่งชิ้น และมี icon ประกอบหัวข้อหรือการ์ด ห้ามมีหน้าที่เป็นตัวหนังสือล้วน (ยกเว้นหน้าปก หน้าคั่น และหน้าปิด) icon ให้เลือกจากคลังของ skill นี้ ไม่วาดใหม่จากรูปทรงพื้นฐานทุกครั้ง

**ข้อ 3 — สีต้องไล่เฉด ไม่ใช้โทนเดียว และต้องสวย** ฐานสีของทั้งชุด: ลูกค้ามี Corporate Identity ให้ใช้ตามนั้น · ลูกค้าไม่มี ให้เลือกชุดสีจากคลังที่มีอยู่แล้วในโฟลเดอร์ `references/` ของ skill นี้ (`catalog-gradients.md` · `color-palette-selection.md` · `color-pairing-guide.md` · โฟลเดอร์ `gradients/`) ห้ามคิดสีขึ้นเอง ทุกองค์ประกอบใช้การไล่เฉด (gradient shading) ไม่ใช่สีทึบสีเดียวทั้งหน้า

**ข้อ 4 — color code ที่บอกความหมาย ต้องต่อเนื่องทั้งเล่ม** สีที่ใช้แทนความหมาย (เช่น สถานะ ระดับ ประเภทงาน) ไม่จำเป็นต้องใช้สีตาม Corporate Identity แต่ต้องคงเส้นคงวา: เรื่องเดียวกันใช้ชุดสีเดียวกันทุกหน้า · หน้าที่สื่อคนละเรื่องใช้ชุดสีคนละชุด · หน้าใดไม่เกี่ยวกับชุดสีไหน ห้ามแสดง legend ของชุดนั้นในหน้านั้น ใน content-spec ต้องประกาศ `palette_base` หนึ่งครั้งต่อชุด และ `topic_id` กับ `color_set` ทุกหน้า เพื่อให้ตัวตรวจอัตโนมัติเทียบได้

**ข้อ 5 — หนึ่งหน้า หนึ่งข้อความ และหัวเรื่องเป็นประโยคสรุป** ทุกหน้ามี action title คือประโยคสมบูรณ์ที่บอกข้อสรุปของหน้านั้น (ไม่ใช่ชื่อหัวข้อ) ยาวไม่เกินสองบรรทัด เนื้อหาต่อหน้าไม่เกินงบคำของโหมดที่เลือก (โหมดนำเสนอสด ไม่เกิน 25 คำ · โหมดเอกสารอ่านเอง ไม่เกิน 75 คำ ตาม `references/design-principles.md`) "วัตถุประสงค์ของหน้า" (หน้านี้ทำให้ผู้ฟังตัดสินใจอะไร) ต้องเขียนไว้ใน content-spec ตอนคิดเท่านั้น **ห้ามปรากฏบนสไลด์** เพราะจะกลายเป็นการบรรยายที่ user เรียกว่า "ลิเก"

**ข้อ 6 — เขียนจากมุมของลูกค้า และทำต่อจากไฟล์ล่าสุดเสมอ** ทุกหน้าตอบว่าลูกค้าได้ประโยชน์อะไร ไม่ใช่มุมภายในของทีมขาย และก่อนแก้สไลด์ชุดที่มีอยู่แล้ว ต้องเปิดอ่านไฟล์รุ่นล่าสุดจากโฟลเดอร์จริงก่อน เพราะ user แก้ไฟล์ด้วยตนเองเป็นเรื่องปกติ (กติกาการอ่านฐานอยู่ที่ skill ice-doc-builder หัวข้อ 0.1)

## วิธีตรวจว่าทำตามกฎ

ผู้สร้างตรวจตัวเองก่อนส่ง และอริสตรวจซ้ำในมิติ D6 (แบรนด์และรูปแบบ) และ D7 (เลย์เอาต์) ด้วยเกณฑ์เดียวกัน: หน้าเนื้อหาที่ไม่มีภาพหรือ icon = ไม่ผ่าน · ตัวอักษรต่อหน้าเกินงบคำ = ไม่ผ่าน ต้องแตกเป็น bullet หรือแยกหน้า · topic_id เดียวกันแต่ color_set ต่างกัน = ไม่ผ่าน · legend ของชุดสีที่ไม่ได้ใช้ในหน้านั้น = ไม่ผ่าน · หัวเรื่องเป็นชื่อหัวข้อแทนประโยคสรุป = ไม่ผ่าน · คำว่า "วัตถุประสงค์" หรือ "objective" ปรากฏบนสไลด์ = ไม่ผ่าน
